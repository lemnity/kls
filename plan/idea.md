**РОЛЬ:**
Ты — senior full-stack архитектор и UI/UX дизайнер. Спроектируй и опиши архитектуру модуля «Создание» для платформы управления проектами.

**КОНЦЕПЦИЯ:**
Визуальный no-code/low-code конструктор, похожий на конструктор чат-ботов (Voiceflow, ManyChat), но предназначенный для управления бюджетами, задачами и цехами. Система нод (узлов), где каждая нода — это «Отдел» или «Цех». Внутри ноды ведется работа с задачами, бюджетом и сотрудниками.

---

### 1. ВИЗУАЛЬНЫЙ КОНСТРУКТОР (CANVAS)

**Рабочая область:** Бесконечное поле (pan and zoom), где отображается схема проекта.

**Ноды:** Прямоугольные блоки. Каждая нода соответствует отделу (например, «Цех металлообработки», «Отдел закупок», «Логистика»).

**Содержимое ноды на канвасе:**
- Название отдела
- **Главная сумма** (согласованный бюджет отдела)
- Цветовой индикатор статуса бюджета (см. пункт 4)

**Связи:** Линии между нодами, показывающие последовательность этапов (стрелки от одного отдела к другому).

---

### 2. ВНУТРЕННЯЯ СТРАНИЦА НОДЫ (DRILL-DOWN)

При клике на ноду канвас «проваливается» внутрь или открывается полноэкранная страница.

**Интерфейс внутри ноды:**

**Шапка:** Название отдела и общая сумма бюджета.

**Поля ввода:** Для внесения данных по стоимости (плановые затраты, фактические затраты, сметы).

**Список задач (Task List):**
- Активные и завершенные задачи отдела
- Кнопка «Создать задачу» (доступна только роли «Главный по цеху»)

**Карточка задачи:**
- **Название** (например, «Собрать смету на стулья»)
- **Исполнители:** Мультиселект из списка сотрудников отдела (например, 3 человека)
- **Статус исполнителя:**
  - Каждый сотрудник имеет свой индикатор
  - Выполнено — зеленый
  - Просрочено или не отмечено — красный
- **Действия руководителя:**
  - Кнопки «Принято» (зеленая галочка) или «Отклонено» (красный крест)

**Логика утверждения:**
- Задача считается выполненной только когда руководитель нажал «Принято»
- При нажатии «Принято» сумма из задачи добавляется в «Согласованную сумму» отдела
- Эта сумма выводится на главный экран (на ноду на канвасе)

---

### 3. РОЛИ И ПРАВА ДОСТУПА

**Администратор/Менеджер проекта:**
- Видит весь канвас
- Может создавать ноды
- Смотрит статистику

**Главный по цеху (Руководитель отдела):**
- Имеет доступ к своей ноде
- Может создавать задачи
- Назначает людей
- Принимает или отклоняет работу

**Сотрудник (Исполнитель):**
- Заходит в ноду
- Видит задачи, назначенные на него
- Может загружать файлы, писать комментарии, отмечать выполнение

---

### 4. БЮДЖЕТНАЯ ЛОГИКА И ЦВЕТОВАЯ ИНДИКАЦИЯ

**Главный нод (родительский контейнер):**
- Имеет **«Главную сумму»** — общий бюджет всего проекта (вводится вручную)
- Имеет фактическую сумму = сумма всех согласованных бюджетов дочерних нод (отделов)

**Правила подсветки для Главного нода:**
- Сумма дочерних нод > Главной суммы → **Красный** (перерасход)
- Сумма дочерних нод < Главной суммы → **Зеленый** (экономия)
- Сумма равна → **Синий** (точное соответствие)

**Нода отдела:**
- Аналогичная логика: сравнивается «Плановый бюджет отдела» с «Суммой принятых задач»

---

### 5. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

**Фронтенд:** React (или Vue) + библиотека для работы с графами (React Flow / Vue Flow) для drag-and-drop и соединений нод.

**Стейт-менеджмент:** Zustand или Redux Toolkit.

**Бэкенд:** Node.js (NestJS) или Python (FastAPI). REST API или WebSockets для real-time обновления статусов (если один сотрудник отметился, у руководителя сразу загорается зеленый).

**База данных:** Опиши структуру SQL (PostgreSQL) или NoSQL (MongoDB) — как хранить ноды, задачи, пользователей, транзакции бюджета.

### 6. ПРИМЕР СЦЕНАРИЯ (USER STORY)

1. Админ создает ноду «Цех сборки» и ноду «Малярный цех»
2. В «Цех сборки» заходит Руководитель, создает задачу «Смета на стулья»
3. Назначает Иванова, Петрова, Сидорова
4. Дедлайн: завтра
5. Иванов и Петров загрузили расчеты и нажали «Готово». Сидоров заболел и ничего не сделал
6. Руководитель смотрит карточку: у Иванова и Петрова — зеленые галочки, у Сидорова — красный восклицательный знак (просрочка)
7. Руководитель жмет «Принято» (частично) или «Отклонено» и возвращает задачу, сняв Сидорова с задачи
8. Сумма принятых смет падает в бюджет отдела
9. Если бюджет отдела превышен, нода на главном канвасе загорается красным
